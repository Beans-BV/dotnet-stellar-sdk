The Stellar network the challenge is bound to.

The server's signing key as a G... account ID (stellar.toml SIGNING_KEY). The server's signature on the challenge is verified against it.

serverHomeDomain string

The server's home domain. A challenge is validated against it when a request names no home domain.

sorobanRpcUrl string

The Stellar RPC URL used to read the latest ledger, from which the client signature expiration is computed.

webAuthDomain string

The web_auth_domain the server binds challenges to. Servers configure this independently of the endpoint URL (the reference server uses the home domain; anchor-platform uses a dedicated config value), so it is taken as configuration here rather than derived from authEndpoint. Defaults to serverHomeDomain when null.

httpClient HttpClient

Optional HTTP client to reuse. Credentials placed in this client's DefaultRequestHeaders are sent to every host it contacts — including a client domain's stellar.toml (a different origin) during client-domain verification. To send credentials only to the auth server, use httpRequestHeaders instead; the SDK does not forward those across origins.

httpRequestHeaders Dictionary<string, string>

Optional headers sent with requests to the auth server. The SDK does NOT forward these to the client domain's stellar.toml fetch, so they are the safe place for auth-server credentials.

signatureExpirationLedgers uint?

How many ledgers after the latest ledger the client signature expires. Defaults to DefaultSignatureExpirationLedgers when null.

resilienceOptions HttpResilienceOptions

Optional retry/timeout options for the HttpClient the SDK creates. Ignored when httpClient is supplied — that client is used as-is.

JwtTokenAsync(string, ICollection<KeyPair>, string?, string?, KeyPair?, ClientDomainEntrySigningDelegate?)

End-to-end SEP-45 flow: fetch challenge, validate, sign, submit, return JWT.

public Task<string> JwtTokenAsync(string clientAccountId, ICollection<KeyPair> signers, string? homeDomain = null, string? clientDomain = null, KeyPair? clientDomainAccountKeyPair = null, ClientDomainEntrySigningDelegate? clientDomainSigningDelegate = null)

Parameters

clientAccountId string

Contract account being authenticated (C... address).

signers ICollection<KeyPair>

Keypairs that authorize the client (contract) entry. May be empty for a contract whose __check_auth requires no signatures (per SEP-45).

homeDomain string

Optional home domain override (for auth servers serving multiple home domains).

clientDomain string

Optional client domain.

clientDomainAccountKeyPair KeyPair

Optional local client-domain signing keypair.

clientDomainSigningDelegate ClientDomainEntrySigningDelegate

Optional remote client-domain signing delegate. Requires clientDomain to be supplied so the SDK can resolve the client's signing public key from its stellar.toml.

Returns

Task<string>

The JWT session token issued by the server.

Remarks

Intentionally does NOT perform SEP-45's client-side transaction simulation / footprint check (the "simulate the signed entries and verify the read_write footprint contains only the expected ledger_key_nonce entries" step in the spec's authentication flow). That step is defense-in-depth: the spec (a draft) writes it as a descriptive flow step rather than an RFC-2119 MUST, the structural validation already pins the invocation (contract id, function name, no sub-invocations, identical invocation across entries, validated args), and no peer SDK implements it. Omitted deliberately; revisit if the spec promotes it to a hard requirement.

SignAuthorizationEntriesAsync(string, string, ICollection<KeyPair>, KeyPair?, ClientDomainEntrySigningDelegate?, string?)

Signs SEP-45 authorization entries: the client (contract) entry with every supplied signer, and optionally the client-domain entry with a local keypair or a remote signing delegate.

public Task<string> SignAuthorizationEntriesAsync(string authorizationEntriesXdr, string clientAccountId, ICollection<KeyPair> signers, KeyPair? clientDomainAccountKeyPair = null, ClientDomainEntrySigningDelegate? clientDomainSigningDelegate = null, string? clientDomainAccountId = null)

Parameters

authorizationEntriesXdr string

Base64 XDR of the challenge's authorization entries.

clientAccountId string

The client account (C... contract address) being authenticated. The entry whose credentials address equals this value is signed with every keypair in signers.

signers ICollection<KeyPair>

Keypairs that authorize the client (contract) entry; a contract may require several. May be empty for a contract whose __check_auth requires no signatures (per SEP-45): the client entry is then returned with its signature-expiration ledger stamped but no signatures appended. An empty collection is intentional and is deliberately not rejected.

clientDomainAccountKeyPair KeyPair

Optional local client-domain signing keypair. Self-sufficient: it carries its own account id, so clientDomainAccountId is not needed when this is supplied.

clientDomainSigningDelegate ClientDomainEntrySigningDelegate

Optional async delegate invoked to sign the client-domain entry when the keypair isn't available locally (typically for remote signing). Must be paired with clientDomainAccountId (which locates the entry to sign, since it cannot be derived from the delegate) — supplying one without the other throws InvalidArgumentsException. Ignored if clientDomainAccountKeyPair is provided.

clientDomainAccountId string

The client-domain signing account (G... address) used to locate the client-domain entry when signing it via clientDomainSigningDelegate. Required with — and only meaningful alongside — that delegate.

Returns

Task<string>

Base64 XDR of the re-encoded, signed authorization entries.

Remarks

Does NOT validate the challenge (server signature, contract id, function name, domain bindings). Call ValidateChallenge(string, string, string?, string?, string?) first, or use the end-to-end JwtTokenAsync(string, ICollection<KeyPair>, string?, string?, KeyPair?, ClientDomainEntrySigningDelegate?) which validates before signing — signing an unvalidated challenge can authorize a hostile server's entry.

Exceptions

InvalidArgumentsException

Thrown if clientDomainSigningDelegate and clientDomainAccountId are not supplied together (absent a local keypair), or if an authorization entry's address matches neither the server, the client account, nor the client-domain account — i.e. no supplied signer can cover it. Failing here surfaces a clear local error instead of letting the server reject the half-signed challenge with an opaque message.

ValidateChallenge(string, string, string?, string?, string?)

Validates a SEP-45 challenge: decodes the XDR, enforces structural + map-key rules via ReadChallenge(string, string, string, string[], string), confirms the client account matches, enforces the client-domain invariant, and verifies the server's Ed25519 signature.

public ChallengeAuthorizationEntries ValidateChallenge(string authorizationEntriesXdr, string clientAccountId, string? clientDomainAccountId = null, string? clientDomain = null, string? homeDomain = null)

Parameters

authorizationEntriesXdr string

Base64-encoded XDR of the challenge's authorization entries.

clientAccountId string

The expected client contract account ID (C... address).

clientDomainAccountId string

Optional expected client-domain signing account. If null, the challenge must not contain client-domain keys.

clientDomain string

Optional client domain that was requested. When supplied, the challenge's client_domain string is validated against it — SEP-45 requires the client to confirm the returned client_domain matches the one it asked for, not just client_domain_account.

homeDomain string

Optional home domain the challenge was requested for. Defaults to the configured server home domain; supply this when the auth server serves multiple home domains so the challenge's home_domain is validated against the one actually requested.

Returns

ChallengeAuthorizationEntries

The parsed, validated challenge (entries + extracted fields + the located server entry).

Remarks

Does not validate the challenge's network_passphrase — that field is on the HTTP response (NetworkPassphrase), not the XDR, and is checked by JwtTokenAsync(string, ICollection<KeyPair>, string?, string?, KeyPair?, ClientDomainEntrySigningDelegate?). A caller using the manual fetch/validate/sign/submit path should compare it themselves.
