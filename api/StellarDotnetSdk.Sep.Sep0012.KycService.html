Implements the client side of SEP-0012 v1.15.0 - KYC API. SEP-0012 is how a wallet uploads KYC (or other) customer information to an anchor once and reuses it across services: it supplies the customer data that SEP-6, SEP-24 and SEP-31 anchor flows ask for, checks its review status, and lets the customer erase it. See SEP-0012.

Remarks

Discovery and authentication. FromDomainAsync(string, HttpResilienceOptions?, string?, HttpClient?, Dictionary<string, string>?, CancellationToken) reads the anchor's stellar.toml and uses KYC_SERVER, falling back to TRANSFER_SERVER as SEP-0012 prescribes. Every endpoint requires a JWT obtained from the same anchor through SEP-10 (ClientWebAuth, for G... and M... accounts) or SEP-45 (ClientWebAuthContract, for C... contract accounts); each request type carries it in its Jwt property. Because every request carries that JWT and customer data, the KYC server must use https; plain http is accepted only for localhost or a loopback IP address in its standard form (such as 127.0.0.1 or [::1]). The same rule applies to a callback URL registered with PutCustomerCallbackAsync(PutCustomerCallbackRequest, CancellationToken).

Response handling. Response bodies are read with a hard size limit of 1 MiB, so a hostile or malfunctioning server cannot exhaust memory by streaming an unbounded body, and the whole exchange — headers and body — is bounded by the Timeout of the client in use (and, for the internal client, by RequestTimeout), so it cannot stall the caller either. A success body must be strict UTF-8, so malformed bytes are rejected rather than replaced; an error body is decoded leniently. Bodies are parsed with DefaultOptions — duplicate properties are rejected, including in error bodies — and statuses and field types are matched against the exact literal sets SEP-0012 defines. A success response that fails any of this raises InvalidKycResponseException. Error statuses raise AuthenticationRequiredException (401, or 403 authentication_required), CustomerNotFoundException (404 from GET/PUT /customer, PUT /customer/verification, PUT /customer/callback or DELETE /customer), PayloadTooLargeException (413) or KycServiceException (anything else, including a 404 from the /customer/files endpoints); each carries the anchor's error text when the error body holds one.

Transport failures surface as HttpRequestException (including a connection that drops while a success body is being read) or TaskCanceledException (cancellation, or a timeout, in which case its inner exception is a TimeoutException). A call on a disposed service throws ObjectDisposedException once its arguments have passed validation. On .NET 8, a request whose URL exceeds the runtime's length limit (an identifier tens of kilobytes long) raises UriFormatException.

Redirects. The internal client does not follow redirects, so a 3xx answer raises KycServiceException and the request body is never replayed to another host. An external client follows redirects if its handler does; the service then rejects any response that comes from a different origin than ServiceAddress, but by that point the request, including its customer data, has already been sent there. It also rejects a response to a request the handler resent with a different method (a POST after a 301, 302 or 303, or a PUT or DELETE after a 303, is resent as GET), whatever its status: a success would not show the change was applied, and an error would answer a request the caller never made, so both raise a plain KycServiceException. Only the final location is visible, so a chain that leaves the origin and returns to it is not detected at all. Disable AllowAutoRedirect on an external client's handler to avoid both.

HttpClient ownership. Pass a shared, long-lived HttpClient in production. When none is given, the service creates an internal one (honouring HttpResilienceOptions) and disposes it in Dispose(); an external client is never disposed by this service.

Initializes a new instance of the KycService class for an explicit KYC server URL. Use FromDomainAsync(string, HttpResilienceOptions?, string?, HttpClient?, Dictionary<string, string>?, CancellationToken) to discover the URL from the anchor's stellar.toml instead.

public KycService(string serviceAddress, HttpClient? httpClient = null, HttpResilienceOptions? resilienceOptions = null, Dictionary<string, string>? httpRequestHeaders = null)

Parameters

serviceAddress string

The absolute https URL of the anchor's KYC server (its KYC_SERVER), without a query, fragment or user info. Plain http is accepted only for localhost or a loopback IP address in its standard form, for local testing.

httpClient HttpClient

Optional shared HTTP client. If null, an internal client is created and disposed with this instance.

resilienceOptions HttpResilienceOptions

Optional retry/timeout options for the internal client. Ignored when httpClient is given. Do not pass options that retry POST requests on a status code, such as ForHorizon() or ForSoroban(): POST /customer/files creates a new file on every attempt, so a retry after the anchor already stored the upload leaves a duplicate behind. Connection-failure retries apply to every method (see WithConnectionRetries()), so they carry the same risk when a connection drops after the upload was received.

httpRequestHeaders Dictionary<string, string>

Optional custom headers added to every request. A header the service sets itself (Authorization, and the Content-Type of a request body) is never overridden by it, and a name that is not a valid HTTP header name is ignored. Do not pass Content-Length: the body's length is computed per request.

Exceptions

ArgumentException

Thrown when serviceAddress is empty, is not an absolute http(s) URL, uses http for a host other than localhost or a standard-form loopback IP address, or contains a query, fragment or user info.
