InteractiveService

Implements SEP-0024 v3.8.0 - Hosted Deposit and Withdrawal for Stellar anchors. SEP-0024 defines a standard protocol for anchors to facilitate deposits and withdrawals using an interactive web interface. This allows users to convert between Stellar assets and fiat currencies or other external assets. The interactive flow works as follows:

  1. Client authenticates with SEP-10 WebAuth to get a JWT token
  2. Client calls the deposit or withdraw endpoint with asset and amount
  3. Server returns a URL for an interactive web interface
  4. Client displays the URL in a popup/webview where user completes KYC
  5. User provides additional details (bank account, amounts, etc.)
  6. Server processes the transaction and updates status
  7. Client polls the transaction status endpoint for updates See SEP-0024

HttpClient Usage: For production code, it is strongly recommended to pass a shared HttpClient instance to the constructor or FromDomainAsync(string, HttpResilienceOptions?, string?, HttpClient?, Dictionary<string, string>?, CancellationToken). If no HttpClient is provided, a new instance will be created internally. While InteractiveService implements IDisposable to clean up internal clients, reusing a single HttpClient instance (or using IHttpClientFactory) is more efficient and avoids socket exhaustion under load.

IDisposable and HttpClient ownership

InteractiveService implements IDisposable because it may create and own an internal HttpClient instance. When you let InteractiveService create its own client (for example, by calling the constructor without passing an HttpClient), you should either wrap InteractiveService in a using block or explicitly call Dispose() when you are finished with it so the internal client is cleaned up.

If you pass an external HttpClient into the constructor or FromDomainAsync(string, HttpResilienceOptions?, string?, HttpClient?, Dictionary<string, string>?, CancellationToken), that client remains owned by the caller. In that case, disposing InteractiveService will not dispose the external client, and you are responsible for managing the HttpClient lifecycle yourself (for example, by reusing a single long-lived instance for performance and resilience).

HttpResilienceOptions

You can configure retry policies, timeouts, and circuit breaker behavior by passing HttpResilienceOptions to the constructor or FromDomainAsync(string, HttpResilienceOptions?, string?, HttpClient?, Dictionary<string, string>?, CancellationToken). These options are only used when creating an internal HttpClient. If you provide your own HttpClient, the resilience options are ignored.
