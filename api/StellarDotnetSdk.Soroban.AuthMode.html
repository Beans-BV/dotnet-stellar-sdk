public enum AuthMode

Remarks

Stellar RPC names these modes enforce, record and record_allow_nonroot, and matches the authMode request field against those literals case-sensitively. The wire spelling is therefore pinned on the members themselves rather than left to whatever enum naming a serializer happens to apply.

Two mechanisms carry that spelling, because neither covers every path on its own. JsonStringEnumMemberNameAttribute only takes effect through a JsonStringEnumConverter, so it needs one to be in play; the type-level JsonConverterAttribute supplies one for callers whose JsonSerializerOptions registers none. Between them, every ordinary serialization of an AuthMode emits the RPC literal — for JsonOptions.DefaultOptions, a bare options instance, and the parameterless JsonSerializer.Serialize overload alike, each covered by AuthModeTest.

Note which of the two actually runs, because it is not the intuitive one. System.Text.Json resolves a converter in a fixed order — a JsonConverterAttribute on the property first, then the options' Converters collection (the first entry whose CanConvert matches), then a JsonConverterAttribute on the type. A type-level attribute is thus the weakest of the three, not an override: under JsonOptions.DefaultOptions, whose collection includes a catch-all JsonStringEnumConverter, that global converter resolves this enum and the attribute below is never consulted. The two agree only because JsonStringEnumConverter honours the member-name attributes. A consumer who registers their own AuthMode converter likewise outranks the attribute below — harmless here, since AuthModeExtensions.ToRequestValue and not the serializer is what puts the value in the authMode request field.

What broke releases 15.0.0 through 16.0.0-beta was not the global registration itself but the absence of any member-name mapping to go with it: a bare JsonStringEnumConverter falls back to the C# member name, so the boxed enum went out as RECORD_ALLOW_NONROOT.
