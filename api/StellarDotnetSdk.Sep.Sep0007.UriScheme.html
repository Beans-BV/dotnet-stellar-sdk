Remarks

The static members work offline. The instance members fetch the origin domain's stellar.toml or POST to a callback with the HttpClient given to the constructor; submitting to Horizon goes through the Server passed in, with that server's own client.

Request signatures cover the URI string exactly as sent (minus the signature parameter), so verification works on the received string and never re-encodes it.

Parameters

httpClient HttpClient

Optional HTTP client to reuse for stellar.toml fetches and callback POSTs. Credentials placed in its DefaultRequestHeaders are sent to every origin domain and callback URL a request names, which are chosen by whoever built the request; do not put secrets there.

Give it a handler with automatic redirects turned off (AllowAutoRedirect = false), as the client the SDK creates has; a default HttpClient and DefaultStellarSdkHttpClient follow redirects. A client that follows redirects on its own turns a callback POST answered with 301/302/303 into a GET, or re-POSTs the signed transaction to wherever a 307/308 points, before this class can intervene. SubmitToCallbackAsync(string, string, CancellationToken) detects that afterwards on a best-effort basis and throws, and for the stellar.toml fetch the client's own redirect limits apply instead of this class's (5 hops, https only, each to a fully qualified domain name on the default port without user info).

Where requests come from untrusted sources and this runs on a server, supply a client whose handler refuses loopback, private and link-local addresses (for example with SocketsHttpHandler.ConnectCallback). This class only limits where redirects may point; the origin domain itself, and any domain a redirect names, can still resolve to such an address.

Its Timeout bounds each stellar.toml fetch and callback POST as a whole, including reading the response body.

resilienceOptions HttpResilienceOptions

Optional retry/timeout options for the HttpClient the SDK creates. Ignored when httpClient is supplied — that client is used as-is. Retries apply to the callback POST too: with MaxRetryCount above zero a signed transaction is sent again after a connection failure (and after any status listed in RetryHttpStatusCodes whose method gate admits POST), so a callback may receive it more than once. Leave retries off here unless every callback you POST to is idempotent.

ParseUri(string)

Parses and validates a SEP-7 URI. It checks:

  • the web+stellar: scheme, a tx or pay operation, no fragment, no lone UTF-16 surrogate;
  • name=value query parameters, none repeated; known parameters are non-empty;
  • no parameter of the other operation (xdr/replace/pubkey/chain are tx-only; destination/amount/asset_*/memo* are pay-only);
  • tx: xdr decodes as a transaction envelope, pubkey is an account id, replace follows the SEP-7 grammar with balanced identifiers, chain is itself a valid SEP-7 URI nested at most 7 levels;
  • pay: destination is a G/M/C address or a federation address (name*domain), amount is a positive amount with at most 7 decimals, asset_code (1–12 alphanumerics) and asset_issuer (G...) come together, memo_type is a SEP-7 memo type and memo fits it (hash memos exactly 32 bytes); account ids and other strkeys must be upper case;
  • callback is url: plus an absolute http(s) URL without whitespace, credentials, a host with no valid IDN form, a fragment, a malformed percent escape, a backslash or a ./.. path segment (SEP-7 allows http; SubmitToCallbackAsync(string, string, CancellationToken) still refuses it except for loopback addresses), msg is at most 300 characters, origin_domain is a fully qualified domain name, signature is 64 base64-encoded bytes.

A request with an origin_domain but no signature is invalid, as SEP-7 specifies. Query values are decoded like an HTML form and the other Stellar SDKs do: + is a space, except in the base64 values (xdr, signature, hash memos), where it stays a +. A % not followed by two hex digits is kept as a literal character, as URLSearchParams keeps it, so the value read is the value shown; only callback rejects one, because there it would change the URL that is POSTed to. Escapes that decode to bytes that are not valid UTF-8 (%FF, %ED%A0%80) make the request invalid: decoders disagree on them (URLSearchParams reads U+FFFD, .NET's own decoder keeps the escape as text), so wallets would read different values. The request signature is not verified here; see VerifySignature(string, string) and VerifyOriginDomainSignatureAsync(string, string?, CancellationToken).

Remarks

Show the request to the user and get their approval first. A request with a replace parameter must have its fields filled in before signing: verify any origin_domain with VerifyOriginDomainSignatureAsync(string, string?, CancellationToken), take GetTransaction(), apply the replacements, sign, and call SubmitTransactionAsync(Sep7Uri, TransactionBase, Server?, CancellationToken).

A request with an origin_domain is signed only after its signature verifies against the domain's current URI_REQUEST_SIGNING_KEY, as SEP-7 requires: this method runs VerifyOriginDomainSignatureAsync(string, string?, CancellationToken) itself, fetching the stellar.toml again. Pass the key that verified when the request was shown to the user as pinnedSigningKey so that a key change in between is caught too.

The transaction is signed for the request's network: its network_passphrase, or the public network when it has none, as SEP-7 specifies. The requester chooses that value, so show GetNetwork() to the user, or compare it with the network the wallet is on, before approving; a request without a passphrase asks for a public-network signature. When the request has no callback, pass a horizonServer for that same network; this method cannot check which network a Server serves.

SubmitToCallbackAsync(string, string, CancellationToken)

POSTs a signed transaction to a SEP-7 callback URL as application/x-www-form-urlencoded with a single xdr field, as SEP-7 specifies. Query parameters already on the URL are kept.

public Task<Sep7SubmitResult> SubmitToCallbackAsync(string callbackUrl, string signedTransactionEnvelopeXdr, CancellationToken cancellationToken = default)

Parameters

callbackUrl string

The callback URL, with or without the url: prefix.

signedTransactionEnvelopeXdr string

The signed base64 XDR transaction envelope.

cancellationToken CancellationToken

Cancels the POST.

Returns

Task<Sep7SubmitResult>

The callback's status code and body (at most 512 KiB). A non-2xx status is returned, not thrown; check IsSuccess.

Remarks

Redirects are not followed: a callback that answers 3xx has its status returned, since following it would either drop the transaction (301/302/303 turn the POST into a GET) or send it to a URL that was never checked (307/308). If the HTTP client given to the constructor follows redirects by itself, the transaction may already have gone to the redirect target; the redirect is then detected afterwards and reported as an HttpRequestException. That detection compares the request's final method and URL with the callback's, so it is best effort: a redirect chain that ends back on the callback URL, or a handler that clones the request before redirecting, escapes it, and a handler that rewrites the request URL without redirecting triggers it.

Any https host is accepted, private and link-local addresses included, as is plain http to any loopback port: SEP-7 lets the requester pick the callback. A service that signs requests on behalf of others should restrict the hosts it POSTs to before calling this method.

Exceptions

ArgumentException

Thrown when the URL is not absolute https (plain http is allowed only for loopback addresses), or when it contains whitespace, control or invisible formatting characters, credentials, a host with no valid IDN form, a fragment, a malformed percent escape, a backslash or a ./.. path segment, which a callback in a parsed request cannot either.

HttpRequestException

Thrown when the POST fails (including a connection dropped mid-response and a request the client's resilience pipeline rejected or timed out), when the HTTP client followed a redirect, or when the response exceeds 512 KiB.

OperationCanceledException

Thrown when cancellationToken is cancelled or the POST, response body included, takes longer than the HTTP client's Timeout.

VerifyOriginDomainSignatureAsync(string, string?, CancellationToken)

Verifies a request's origin_domain as SEP-7 prescribes, before a wallet may show the domain: the URI must be valid and carry both origin_domain and signature; the domain's stellar.toml is fetched (not cached, as the spec recommends) and must publish a valid URI_REQUEST_SIGNING_KEY; and the signature must verify against that key.

public Task<string> VerifyOriginDomainSignatureAsync(string uri, string? pinnedSigningKey = null, CancellationToken cancellationToken = default)

Parameters

uri string

The signed URI, exactly as received.

pinnedSigningKey string

The URI_REQUEST_SIGNING_KEY the wallet cached for this domain from an earlier request, if any. SEP-7 requires wallets to alert the user when the key changes; a different key raises UriRequestSigningKeyChangedException. Cache the returned key for the next request, keyed by the domain in lower case (domain names are case-insensitive, and OriginDomain is returned as sent). Keys are compared case-insensitively.

cancellationToken CancellationToken

Cancels the stellar.toml fetch.

Returns

Task<string>

The URI_REQUEST_SIGNING_KEY the signature verified against.

Remarks

Only the URI_REQUEST_SIGNING_KEY of the stellar.toml's root table is read, with a non-recursive reader rather than the general StellarToml parser: the domain is chosen by whoever wrote the URI, and that parser overflows the stack on small hostile documents. The whole document must be valid UTF-8, as TOML requires, including the tables after the root one. Redirects of the stellar.toml request that reach this class are followed, at most 5 of them and only to https URLs on a fully qualified domain name, the default port and no user info, so a redirect reaches no further than an origin domain could. With the SDK's own client that is every redirect; a client that follows redirects itself applies its own limits first (see the constructor).
