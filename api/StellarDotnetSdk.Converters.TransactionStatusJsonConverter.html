Remarks

The sibling of SendTransactionStatusEnumJsonConverter, for the same reason and with the same registration requirement: it must stay ahead of JsonStringEnumConverter in DefaultOptions or the catch-all shadows it wherever the enum is deserialized on its own. Status additionally applies this converter with a property-level JsonConverterAttribute, which System.Text.Json resolves ahead of any options' converter collection — so the property path stays strict whichever JsonSerializerOptions a consumer supplies.

The stakes here are higher than for sendTransaction. The standard converter accepts bare integers and maps them by ordinal, so "status": 1 read as SUCCESS — on the endpoint callers poll to decide whether a payment settled. It is also case-insensitive, and it happily produces undefined values: a response of "status": 7 yielded the enum value 7, which matches none of the three members and so silently fails every comparison a caller writes.

Remarks

Required because this converter is attached to the enum type. Without the two property-name overloads System.Text.Json has no way to turn the enum into a JSON object key and throws NotSupportedException for a Dictionary<TransactionStatus, T> — which is not a JsonException, so a caller's catch (JsonException) would miss it. The literal set is the same one Read(ref Utf8JsonReader, Type, JsonSerializerOptions) accepts, so a key round-trips exactly like a value.
