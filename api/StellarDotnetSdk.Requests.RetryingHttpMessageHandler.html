HTTP message handler that implements retry logic for connection failures (network errors, DNS failures, etc.) and for configured HTTP status codes (see RetryHttpStatusCodes). Honors the Retry-After response header when RespectRetryAfter is true. By default, only safe HTTP methods (GET, HEAD, OPTIONS) are retried on status codes; connection-failure (exception) retries apply to all methods.

Retries re-send the same HttpRequestMessage instance, so request bodies must be re-readable, buffered content (StringContent, ByteArrayContent, FormUrlEncodedContent — all of the SDK's own requests qualify). A non-seekable StreamContent body fails on the second attempt.

Cancellations are never retried: when HttpClient.Timeout fires it cancels the request's token, so the resulting TaskCanceledException propagates immediately, exactly like a user-initiated cancellation.

Methods

Send(HttpRequestMessage, CancellationToken)

Sends an HTTP request through the resilience pipeline synchronously. Mirrors SendAsync(HttpRequestMessage, CancellationToken) so that Send(HttpRequestMessage) receives the same retry, circuit-breaker, and timeout behavior instead of silently bypassing the pipeline (a DelegatingHandler's inherited sync Send forwards straight to the inner handler). The inner handler chain must itself support synchronous Send (SocketsHttpHandler does over HTTP/1.1). This override exists only on net8.0/net10.0; on the netstandard2.1 assembly (which net5–net7 apps resolve) synchronous Send throws NotSupportedException — see the base-class note above.
