SorobanAddressCredentials

Represents Soroban credentials that authenticate a specific address for contract invocation authorization. Contains the authorizing address, a unique nonce, a signature expiration ledger, and the cryptographic signature.

SorobanAddressCredentialsBase

Shared base for the address-bearing Soroban credentials. V1 (SorobanAddressCredentials) and V2 (SorobanAddressCredentialsV2) have identical fields; they differ only by XDR discriminant and by the signing payload used to produce Signature.

SorobanAddressCredentialsV2

Protocol 27 (CAP-0071-02) address-bound credentials. Wire layout is identical to SorobanAddressCredentials, but the signature is computed over the address-bound preimage (ENVELOPE_TYPE_SOROBAN_AUTHORIZATION_WITH_ADDRESS), preventing signature replay between accounts that share a private key.

SorobanAddressCredentialsWithDelegates

Protocol 27 (CAP-0071-01) delegated credentials: a root address credential plus an ordered set of delegate signatures that authenticate on its behalf.

SorobanCredentials

Abstract base class for Soroban authorization credentials. Credentials identify and authenticate the entity authorizing a contract invocation.

SorobanDelegateSignature

High-level wrapper for a single delegate signature in a delegated authorization (Protocol 27, CAP-0071-01). Recursive: a delegate may itself carry nested delegates.

SorobanDelegatedRoot

The root address credential of a delegated authorization (SorobanAddressCredentialsWithDelegates): its bare address/nonce/expiration/signature fields. On the wire CAP-0071-01 embeds these as a discriminant-free SorobanAddressCredentials struct, and the signature is computed over the address-bound (delegated) payload. Unlike SorobanAddressCredentials this type is deliberately NOT a serializable SorobanCredentials: serializing the root on its own would emit a standalone credential the network rejects, so the type makes that misuse impossible to express rather than merely documenting against it.

SorobanSourceAccountCredentials

This simply uses the signature of the transaction (or operation, if any) source account and hence doesn't require any additional payload.

UploadContractHostFunction

UploadContractOperation

Operation that invokes a Soroban host function to upload compiled smart contract Wasm bytecode to the Stellar network. The uploaded Wasm can subsequently be used to create contract instances via CreateContractOperation.
