AssetIdentifier

An asset in the SEP-38 Asset Identification Format, <scheme>:<identifier>.

QuoteService

Client for SEP-0038 v2.5.0 — Anchor RFQ API. Lets a wallet discover which assets an anchor exchanges, fetch indicative prices, and request firm quotes whose id it then passes as quote_id to a SEP-6, SEP-24 or SEP-31 transaction. See SEP-0038.

Authentication

InfoAsync(string?, CancellationToken), PricesAsync(PricesRequest, CancellationToken) and PriceAsync(PriceRequest, CancellationToken) accept an optional JWT, which the anchor may use to personalize the response. PostQuoteAsync(QuoteRequest, CancellationToken) and GetQuoteAsync(string, string, CancellationToken) require one. Obtain it with SEP-10 (JwtTokenAsync(string, ICollection<KeyPair>, ulong?, string?, string?, KeyPair?, ClientDomainSigningDelegate?)) for G.../M... accounts or SEP-45 (JwtTokenAsync(string, ICollection<KeyPair>, string?, string?, KeyPair?, ClientDomainEntrySigningDelegate?)) for contract accounts.

Amounts

Amounts and prices are decimal values. Requests send them as invariant-culture strings, keeping the scale given; responses are read exactly: a value that decimal cannot hold without rounding fails with UnexpectedResponseException rather than being approximated.

Errors

Invalid arguments — including the sell/buy amount exclusivity rules, a zero or negative amount, a string property that is empty or whitespace rather than null, and a JWT that is not printable ASCII without whitespace — throw ArgumentException from the returned task, before anything is sent. Error responses map to BadRequestException (400), PermissionDeniedException (403), QuoteServerNotFoundException (404) and UnexpectedResponseException (anything else, including a 3xx, or an unusable success body); all derive from QuoteServerException. A Retry-After header on an error response (typically 429 or 503) is exposed as UnexpectedResponseException's RetryAfterDelay. Response bodies are read up to 1 MiB, and parsed with the SDK's hardened JSON options, which reject duplicated mapped properties. An error body over the limit is dropped (Error and ResponseBody are then null) but the status still selects the exception type; a success body over the limit raises UnexpectedResponseException. A leading UTF-8 byte order mark is skipped.

A success body is also checked against the request: a firm quote must carry a usable id, the requested asset pair, no delivery method other than the one requested (compared without regard to case), and an expiry no earlier than the requested expire_after; prices and amounts must be greater than zero, and a decimals count must not be negative. A response that fails these checks raises UnexpectedResponseException, whose ResponseBody still holds what the anchor sent (for POST /quote, the id of the quote it already created).

Transport failures surface as HttpRequestException (including a connection that drops while a success body is being read) or TaskCanceledException (cancellation, or a timeout, in which case its inner exception is a TimeoutException). The whole exchange — headers and body — is bounded by the Timeout of the client in use (and, for the internal client, by RequestTimeout), so a server that trickles its body cannot stall the caller. An internal client with EnableCircuitBreaker set throws Polly's BrokenCircuitException while the circuit is open, and a call on a disposed service that owns its client throws ObjectDisposedException. On runtimes before .NET 10, a request whose URL exceeds the runtime's length limit (a quote id tens of kilobytes long) raises UriFormatException.

Redirects

The internal client does not follow redirects, so a 3xx answer raises UnexpectedResponseException and a request is never replayed to another host. A caller-owned client follows redirects if its handler does; the service then rejects any response that comes from a different origin than the quote server, but by that point the request, its body and the custom headers have already been sent there (on .NET's SocketsHttpHandler, not the JWT, whose Authorization header it drops on a redirect). Only the final location is visible, so a chain that leaves the origin and returns to it is not detected at all. Disable AllowAutoRedirect on a caller-owned client's handler to avoid both. The check compares the final request URI, so a caller's handler that rewrites it to another origin (a gateway, for example) is rejected the same way.

Retries

POST /quote is not idempotent: every call creates a new firm quote that the anchor holds in reserve until it expires. Do not pass ForHorizon() or ForSoroban(): both retry POST on a 408, 429, 500, 502, 503 or 504 answer, so one call can reserve two quotes. Use WithConnectionRetries() (which still replays a POST whose response was lost in transit) or NoRetry().

HttpClient ownership

Pass a shared HttpClient (or one from IHttpClientFactory) in production; it stays owned by the caller and is not disposed with this service. When none is passed, the service creates its own, configured by HttpResilienceOptions, and disposes it in Dispose().
