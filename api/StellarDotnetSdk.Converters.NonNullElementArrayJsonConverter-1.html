Remarks

RespectNullableAnnotations constrains the array reference, never its contents, so [null] otherwise produced an array holding null despite a non-nullable element type — and the compiler then suppressed exactly the null checks that would have caught it, so a plain foreach over the result threw NullReferenceException at the caller instead of failing at deserialization like every other malformed-payload path.

The check lives in a converter rather than in the property's init accessor because the two entry points want different exception types, and a converter is the only place that can tell them apart. System.Text.Json runs a property-level converter before assigning the value, so a malformed payload fails here as a JsonException; an accessor throwing ArgumentException — the right type for a rejected argument — still guards the ordinary C# path, and escapes JsonSerializer.Deserialize unwrapped, which is why it cannot serve as the wire-format guard as well.

Each guarded property names a sealed subclass rather than closing this type directly, because a JsonConverterAttribute can only name a type with an accessible parameterless constructor. That is not merely a style constraint: the System.Text.Json source generator emits SYSLIB1220 and silently drops a converter it cannot construct, and the property's ArgumentException guard would then surface out of JsonSerializer.Deserialize in place of the JsonException documented here.

Attach these with a property-level JsonConverterAttribute; never add one to Converters. Both directions read and write the array by delegating to JsonSerializer, which is safe only while the converter is invisible to the options being used — a global registration makes that delegation resolve back here and recurse until the process dies. Because a StackOverflowException cannot be caught, and because these types are necessarily public and look exactly like the converters this SDK does register globally, both Read(ref Utf8JsonReader, Type, JsonSerializerOptions) and Write(Utf8JsonWriter, T[]?, JsonSerializerOptions) check for that registration and raise an ordinary InvalidOperationException instead.

This rejects nothing a conforming server can send: Stellar RPC's Go types are slices of structs (and, for events and auth, of plain string) rather than of pointers, so encoding/json cannot emit a null element for any of them. It is a guard against a non-conforming or hostile endpoint.

Exceptions

JsonException

Thrown when the array contains a null element. Nothing of this array is written when it does, but — as for any converter that fails part-way through a document — a Utf8JsonWriter the caller owns and reuses across serializations is left with unbalanced depth and should be discarded rather than written to again. Serializing through Serialize(object, Type, JsonSerializerOptions) and its overloads is unaffected, because the writer does not outlive the call.
