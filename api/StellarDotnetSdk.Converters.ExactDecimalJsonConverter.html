Remarks

Parse(string, NumberStyles, IFormatProvider) silently rounds a value with more significant digits than the type holds — "0.1234567890123456789012345678901" reads as a 28-place approximation — and AllowReadingFromString inherits that. For a quoted price or amount that the caller will echo back to the anchor, or multiply to check the anchor's arithmetic, a silently different number is worse than an error, so this converter compares the parsed scale against the digits that arrived and throws JsonException on any loss. Trailing fractional zeros carry no value and are not counted, so "5.00" is accepted (and keeps its scale: decimal preserves it).

The accepted grammar is a decimal literal: an optional leading -, one or more digits, an optional . followed by one or more digits, and an optional exponent (e or E, an optional sign, one or more digits). SEP-38 defines amounts only as strings, and a server serializing a java.math.BigDecimal emits "1E-7" for a small price, so an exponent is accepted when the value it denotes fits exactly; such a value is read in its shortest form, so "1.50E1" reads as 15, not 15.0. A leading + or ., whitespace, group separators, and culture-specific decimal separators are rejected.

Writes the invariant-culture string form, which round-trips exactly.

Attached per property with JsonConverterAttribute. It is public so that a consumer's source-generated JsonSerializerContext can instantiate it. Do not register it on Converters: every decimal those options handle would then be read from a quoted string as well as a bare number, rejected instead of rounded when decimal cannot hold it exactly, and written as a string rather than a number.
