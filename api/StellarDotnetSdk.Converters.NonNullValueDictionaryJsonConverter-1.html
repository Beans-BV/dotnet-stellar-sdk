Remarks

The dictionary counterpart of NonNullElementArrayJsonConverter<T>, with the same JSON path repair and the same registration guard; that type's remarks explain both. RespectNullableAnnotations constrains the dictionary reference, never its values, so {"first_name": null} otherwise produced an entry holding null despite a non-nullable value type, and the caller hit a NullReferenceException on first use.

The check lives in a converter, attached with a property-level JsonConverterAttribute, so that it runs on every deserialization path: the SDK's own parsing, a caller's options, and a caller's source-generated JsonSerializerContext. Each guarded property names a sealed subclass, because the attribute can only name a type with an accessible parameterless constructor.

Never add one to Converters: both directions delegate to JsonSerializer for the same dictionary type, which would then resolve back to this converter and recurse until the process dies. Both directions check for that registration and raise an InvalidOperationException instead.

Unlike the array converter, writing does not check the values: the response types have no accessor that rejects a null value, so a dictionary built in code serializes as written, and reading that JSON back fails. The guard exists for payloads from a server.
